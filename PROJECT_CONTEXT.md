# PROJECT_CONTEXT — Glassgram

Дата подготовки контекста: 25 ноября 2026 года. Архив предназначен для восстановления контекста разработки в ChatGPT. Исходный каталог `C:\Glassgram` при подготовке не изменялся.

## 1. Назначение и состав

Glassgram — настольный Telegram-клиент для Windows с интерфейсом в стиле Liquid Glass, локальной интеграцией Ollama и встроенным режимом ИИ-агента. Основная реализация находится в `src/Glassgram` и написана на C#/WinUI 3. Telegram подключается напрямую через TDLib. Версия 0.6.1 добавляет правую панель профиля и стикеров, реальные данные TDLib и отправку WEBP/TGS/WEBM-стикеров.

В `reference/Telegram_AI_V9_Messenger` сохранён отдельный, исторически самостоятельный Python-проект Telegram AI V9. Он использует Telethon, локальную Ollama и собственную панель управления/мессенджер. Это справочная реализация отдельного агента и Telegram-бота; она не является библиотекой, которую C#-клиент загружает во время работы.

Состав архива:

- `src/Glassgram` — исходники основного клиента, XAML, ресурсы, manifest и файл проекта;
- `reference/Telegram_AI_V9_Messenger` — исходники отдельного агента, backend/UI мессенджера, сценарии запуска/сборки и README версий V7–V9;
- `Glassgram.slnx`, `Build.cmd`, `Start.cmd` — решение и сценарии основного приложения;
- `README.md` — документация основного клиента;
- `PROJECT_CONTEXT.md` — этот файл.

В архив намеренно не включены Git-объекты, сборки, зависимости, кеши, модели Ollama, логи, токены, ключи, Telegram-сессии, базы памяти, история сообщений и пользовательские настройки.

## 2. Архитектура основного приложения

### UI и жизненный цикл

- `App.xaml` / `App.xaml.cs` — ресурсы приложения, запуск главного окна и журналирование необработанных ошибок в локальный каталог приложения.
- `MainWindow.xaml` — единое главное окно: навигация, авторизация Telegram, список чатов, лента сообщений, просмотр медиа, локальный чат с Ollama, ИИ-агент и настройки оформления.
- `MainWindow.xaml.cs` — навигация, настройки, Liquid Glass, темы/обои, прямой локальный чат с Ollama и встроенный агент анализа открытого чата.
- Partial-классы `MainWindow.*.cs` разделяют Telegram-авторизацию, мессенджер, действия над сообщениями, медиа, контекстные меню и горячие клавиши.
- `Controls/GlassPanel.cs` и XAML-ресурсы реализуют визуальные стеклянные панели; `Assets` содержит иконку и PNG.

### Telegram/TDLib слой

- `Telegram/TdClient.cs` — тонкая асинхронная обёртка над нативным `tdjson`: создание клиента, отправка JSON-запросов, очередь ответов/обновлений, отмена и освобождение ресурсов.
- `Telegram/TelegramModels.cs` — преобразование TDLib JSON в UI-модели чатов и сообщений, позиции чатов, медиа и observable-состояние.
- `MainWindow.Telegram.cs` — параметры TDLib и конечный автомат авторизации: API ID/hash, телефон или QR, код, email-код и облачный пароль.
- `MainWindow.Messenger.cs` — загрузка/сортировка списка чатов, пагинация истории, применение обновлений TDLib и переключение активного чата.
- `MainWindow.Messenger.Actions.cs` — отправка, ответ, редактирование, удаление, прочтение, набор текста и вложения.
- `MainWindow.Media.cs` — ленивое скачивание и показ фото, видео, GIF, документов, WebM/TGS-стикеров.
- `Telegram/SessionStorage.cs` — каталоги базы/файлов TDLib и случайный ключ базы, защищённый Windows DPAPI для текущего пользователя.
- `Telegram/MessageHistoryCache.cs` — локальный кеш до 500 сообщений на чат, также защищённый DPAPI.

### Ollama и встроенный ИИ-агент

- Разрешён только loopback HTTP endpoint, по умолчанию `http://127.0.0.1:11434`.
- `GET /api/tags` получает список локальных моделей.
- `POST /api/chat` используется как обычным локальным ИИ-чатом, так и встроенным агентом.
- Встроенный агент берёт последние доступные сообщения уже открытого Telegram-чата, формирует системную инструкцию и пользовательскую задачу (суммаризация, черновик, перевод или произвольная задача), затем показывает результат в отдельной панели.
- Результат встроенного агента не отправляется в Telegram автоматически. Это сознательная граница безопасности: пользователь сам решает, использовать ли предложенный текст.

### Локальные данные основного клиента (не включены в архив)

Рабочие данные создаются в `%LOCALAPPDATA%\Glassgram`:

- `settings.json` — endpoint Ollama, выбранная модель и параметры интерфейса;
- `telegram.credentials` (по логике приложения) — API ID/hash, защищённые DPAPI;
- `Telegram/database`, `Telegram/files`, `Telegram/database.key` — база, файлы и ключ TDLib;
- `MessageCache` — зашифрованный кеш истории;
- журналы ошибок и скачанные/временные медиа в соответствующих локальных каталогах.

Эти каталоги персональны и не должны передаваться вместе с исходным кодом.

## 3. Архитектура отдельного Python-агента V9

- `agent.py` — основной процесс. Загружает `.env`, подключает пользовательский Telegram-аккаунт через Telethon, принимает события, ведёт белый список разрешённых чатов, управляет согласием/отказом, памятью, очередями и вызывает Ollama.
- `messenger_backend.py` — API мессенджера поверх Telethon: диалоги, история, поиск, сообщения, ответы, редактирование, удаление, прочтение, файлы/стикеры и поток событий.
- `messenger_ui.py` — вкладка мессенджера PySide6, история и вложения, уведомления Windows через системный трей.
- `control.py` — основная PySide6-панель: запуск/остановка агента, белый список, память, настройки модели, мониторинг CPU/GPU/RAM/VRAM, журналы и мессенджер.
- `control_legacy.py` — резервная панель Tkinter.
- `Start_AI.cmd` / `Start_AI.vbs` / `Start_Legacy.cmd` — варианты запуска; `Install_UI.cmd` устанавливает UI-зависимости; `Build_EXE.cmd` собирает оболочку панели через PyInstaller.

Агент использует:

- `.env`: `API_ID`, `API_HASH` и необязательные параметры (файл отсутствует в архиве);
- `assistant.session`: Telethon-сессия (отсутствует);
- `allowed.txt`: белый список ID чатов (отсутствует);
- `memory.sqlite3`: память, настройки, согласие и метаданные (отсутствует);
- локальный API `127.0.0.1:8765` с одноразовым runtime-токеном в `.agent_runtime.json` (runtime-файл отсутствует);
- Ollama `http://127.0.0.1:11434/api/chat`, модель по умолчанию `qwen3.5:9b`;
- DDGS/DuckDuckGo только при явном запросе интернет-поиска.

Ключевое отличие: основной Glassgram использует TDLib и встроенный draft-only агент; отдельный V9 использует Telethon и способен автоматически отвечать только в разрешённых чатах при наличии согласия. Между двумя реализациями нет общего процесса, IPC или общей базы.

## 7. Известные баги и ограничения

Для основного клиента в репозитории нет отдельного актуального bug tracker. По коду, README и истории известны следующие ограничения/риски:

- Версия проекта и корневой README синхронизированы на `0.6.0`.
- Проект нацелен на .NET 11 и Windows SDK 26100; на машине без соответствующего preview/актуального SDK сборка не пройдёт.
- Клиент Windows-only и x64-only.
- Ollama endpoint специально ограничен обычным HTTP loopback; удалённый сервер и HTTPS текущей проверкой адреса не поддерживаются.
- Встроенный агент использует только сообщения, которые уже загружены в память открытого чата, а не гарантированно всю историю.
- Последовательность исправлений в последних коммитах показывает недавние регрессии порядка/позиций чатов и stale media IDs; последние коммиты должны их устранять, но реальный Telegram следует перепроверить.
- README заявляет Windows-уведомления, TDLib и медиа, однако автоматизированные интеграционные тесты в архиве отсутствуют.

Ограничения отдельного V9, прямо отмеченные его README:

- Встроенный Python-мессенджер поддерживает личные чаты, но не группы.
- За один запрос загружается 40 сообщений; старые загружаются вручную.
- Файлы ограничены 50 МБ.
- Анимированные стикеры могут отображаться только миниатюрой/символом; показываются до 30 недавних стикеров, а не все наборы.
- Просмотр сообщения сам не отмечает его прочитанным; отметка отправляется явно.
- Windows может объединять уведомления; возможны дубли при одновременно запущенном Telegram Desktop.
- Реальные Telegram, Ollama, PySide6, Windows-уведомления и PyInstaller-сборка не были проверены в среде подготовки V9.
- Liquid Glass в PySide6 — стилизация, а не системный blur macOS.

## 10. Сборка и запуск основного Glassgram

Требования:

1. Windows 10 build 19041 или новее, рекомендуется Windows 11.
2. Visual Studio с Windows App SDK/Windows Desktop workload либо совместимый .NET 11 SDK и Windows SDK 10.0.26100.
3. Windows x64.
4. Для Telegram — собственные `api_id` и `api_hash` с `my.telegram.org`.
5. Для ИИ — установленная и запущенная Ollama с хотя бы одной локальной моделью.

Сборка Debug из корня проекта:

```powershell
dotnet restore .\Glassgram.slnx
dotnet build .\src\Glassgram\Glassgram.csproj -c Debug -p:Platform=x64
```

Либо запустить `Build.cmd`. Запуск Debug-сборки — `Start.cmd`.

Self-contained publish:

```powershell
dotnet publish .\src\Glassgram\Glassgram.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:Platform=x64 -o .\release
```

После запуска:

1. Ввести Telegram API ID/hash и пройти авторизацию по телефону либо QR.
2. Запустить Ollama (`ollama serve`, если сервис не запущен).
3. Установить модель, например `ollama pull qwen3.5:9b` (модель в архив не входит).
4. В настройках оставить `http://127.0.0.1:11434` или указать другой loopback HTTP-адрес.
5. Нажать «Проверить Ollama», выбрать модель.

## 11. Запуск отдельного Telegram AI V9

Требования: Python 3, Ollama и зависимости:

```powershell
python -m pip install telethon requests python-dotenv ddgs pillow psutil PySide6
```

В каталоге `reference/Telegram_AI_V9_Messenger` локально создать `.env` (не коммитить и не передавать):

```dotenv
API_ID=123456
API_HASH=replace_with_your_telegram_api_hash
OLLAMA_CONTEXT=16384
```

Первый запуск `python agent.py` создаст `assistant.session` после авторизации. Для панели запустить `Start_AI.cmd`; при проблемах PySide6 — `Start_Legacy.cmd`. Белый список настраивается через UI и хранится в `allowed.txt`. Перед автоответами необходимо получить согласие собеседника.

Опциональная сборка оболочки панели: `Build_EXE.cmd`. Она не делает агента полностью автономным: Python, зависимости, `agent.py`, Ollama и рабочие файлы всё равно нужны.

## 12. Правила безопасности при дальнейшей передаче

Никогда не добавлять в архив:

- `.env`, `*.session`, `*.session-journal`, `.agent_runtime.json`;
- `allowed.txt`, `memory.sqlite3`, любые SQLite/TDLib базы;
- `%LOCALAPPDATA%\Glassgram`, Telegram database/files, кеши сообщений и медиа;
- `settings.json`, пользовательские заметки, аватары, журналы, экспорт переписки;
- Telegram API hash, токены, ключи, номера телефонов, email, ID/имена реальных собеседников;
- каталог моделей Ollama, `bin`, `obj`, `release`, `.vs`, зависимости Python/Node/.NET и собранные EXE/DLL.

Перед каждой новой передачей следует повторно просканировать архив на секреты и просмотреть полный список файлов.
